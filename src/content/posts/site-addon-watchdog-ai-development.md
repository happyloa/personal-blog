前陣子開發了 WordPress 安全外掛 [Site Add-on Watchdog](https://tw.wordpress.org/plugins/site-add-on-watchdog/)，用來自動監控網站已安裝的外掛有沒有安全漏洞。這次從需求分析到程式碼撰寫，幾乎全程都與 AI 協作，想記下這段開發經驗。

## 為什麼要做這個外掛

WordPress 的外掛生態系很豐富，但也因此埋了不少資安隱患。很多網站管理者不會主動追蹤外掛的安全性更新，等到被駭了才知道有漏洞。

這個外掛的目的就是自動化這個監控流程。它會定期檢查網站安裝的外掛版本，比對已知的安全漏洞資料庫，如果發現有風險就主動通知管理者。

## 主要功能

這個外掛包含幾個核心功能：

**自動化資安監控**

- 定期掃描網站已安裝的外掛
- 比對外掛版本與 Changelog 中的安全修補
- 整合 WPScan API 查詢已收錄的漏洞資料

**通知系統**

- 支援 Webhooks 串接
- 可通知到 Slack、Discord、Microsoft Teams
- 讓運維團隊能即時收到警報

**管理後台介面**

- 清楚列出所有外掛的安全狀態
- 一目瞭然地看到哪些外掛需要更新
- 提供漏洞詳細資訊和修補建議

## AI 輔助開發的體驗

這個專案全程使用 Claude 和 Google Antigravity IDE 輔助開發，和我以前的開發方式差很多。

### 需求拆解階段

一開始我只有一個模糊的想法：「我想做一個能監控 WordPress 外掛安全性的工具」。先跟 AI 討論這個需求應該怎麼拆解，它幫我列出了幾個主要模組：

- 外掛掃描器
- 漏洞資料庫比對引擎
- 通知系統
- 後台管理介面

有了這個架構之後，開發就有方向了。

### 程式碼撰寫階段

WordPress 外掛開發有一套自己的規範，像是 Hook 機制、設定頁面的寫法、資料庫操作等等。老實說我之前沒有從零開始寫過 WordPress 外掛，很多細節都不熟。

這時 AI 幫了不少忙。我描述功能後，它會提供 Hook、設定頁面等實作範例，讓我比較快找到方向。不過，產生的程式碼仍需要對照 WordPress Plugin Handbook，確認用法和版本是否合適。

### 除錯階段

開發過程中遇到問題，也是直接貼給 AI 看。像是 WordPress 的 cron job 為什麼沒有正常執行、API 回傳的資料格式怎麼解析，這些問題 AI 都能很快給出解答。

## 技術細節

### WPScan API 整合

外掛的核心功能是漏洞偵測，這部分整合了 WPScan API。WPScan 維護 WordPress 相關的已知漏洞資料庫；查不到紀錄不代表外掛一定安全，仍要留意資料收錄的範圍與時間。

整合的流程是：先取得網站已安裝的外掛清單與版本，再向 WPScan API 查詢已知漏洞，比對版本是否受影響。有相關紀錄時，就保存資訊並觸發通知；CVE 編號則依資料庫收錄的內容呈現。

外掛也會比對官方 Changelog 中的安全修補字樣，作為資料庫尚未收錄時的輔助線索。這種字樣比對不能單獨證明某個版本有漏洞，也不能因為沒找到字樣就判定安全。查看通知時，還需要核對受影響與已修補的版本範圍。

### Webhook 通知機制

通知系統採用 Webhook，使用者可以設定要通知到 Slack、Discord、Teams，或串接自己的系統。

Webhook 可以透過 HTTP 把通知送到指定網址，省去另外建立訊息機器人的部分流程。不過，Slack、Discord、Teams 接受的 payload 格式不一定相同，仍要依各平台的欄位與規格組出內容；不能把同一份 JSON 原封不動送到所有接收端。

### 排程機制

為了減少手動檢查，安全掃描需要定期執行。這裡用 WordPress 內建的 WP-Cron 處理排程。

WP-Cron 預設依網站請求觸發，因此流量低的網站可能延後執行。能不能接受延遲，要看掃描需求；如果需要固定時間執行，就要另外安排系統排程。

## 開發過程的反思

這次用 AI 輔助開發的體驗讓我對開發流程有了新的想法。

### AI 能做什麼

這次開發時，AI 在 WordPress Hook、設定頁面的 HTML 結構、AJAX 請求處理等有固定寫法的部分，能快速提供初稿。我仍要核對規範，並確認實際執行結果。

查閱 WPScan 文件時，AI 也能協助整理端點和呼叫範例。拿到初稿後，我仍要確認認證方式、回傳格式與錯誤處理，才能接進外掛。

### 還是需要人來判斷

不過 AI 給的程式碼不能直接複製貼上就用。還是要自己理解它在做什麼，確認邏輯是對的。有時候 AI 會生成看起來很合理但其實有問題的程式碼，這時候就要靠自己的判斷力。

架構的設計也是一樣。AI 可以給建議，但最後的決定還是要自己做。畢竟只有自己最清楚專案的需求和限制。
