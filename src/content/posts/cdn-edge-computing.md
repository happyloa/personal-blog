當你在台灣打開一個架設在美國紐約的網站，資料可能需要跨洲往返。延遲取決於路由和網路狀況，再加上伺服器處理與檔案下載，畫面就可能要等一段時間。

Facebook、Netflix 這類大型網站在台灣也能快速開啟，其中一個原因就是使用了 CDN（Content Delivery Network）。

## CDN 是什麼？

CDN 是由一群分佈在世界各地的伺服器組成的網路。它們的功能很單純：**快取（Cache）** 原始網站的內容，並且就近提供給使用者。

### 運作原理

1. **Origin Server（原始伺服器）**：這是你架設網站的地方（例如在紐約）。
2. **Edge Server（邊緣伺服器）**：這是 CDN 廠商（如 Cloudflare, AWS CloudFront）在世界各地機房裡的伺服器（例如在台北）。

以下假設圖片可以公開快取，而且請求被送到台北的節點。實際節點取決於 CDN 的路由，不一定就是地理上最近的機房。

當使用者第一次請求這張圖片：

1. 請求先送到**台北的 Edge Server**。
2. Edge Server 發現自己沒有這張圖，於是向**紐約的 Origin Server** 要。
3. Origin Server 把圖片傳給 Edge Server。
4. Edge Server 把圖片傳給使用者，並依快取規則保存一份。

另一位使用者請求相同快取版本、而且快取仍可使用時：

1. 請求送到**台北的 Edge Server**。
2. Edge Server 發現自己有快取，**直接傳給使用者**。
3. 圖片不用重新從紐約取得，可以省下這段往返時間。

## 什麼是 Edge Computing（邊緣運算）？

CDN 常用來快取圖片、CSS、JS 等靜態檔案，也能依規則快取 HTML 或 API 回應。個人化購物車、登入後的資料則要特別小心，不能把某個人的內容放進所有人共用的快取。

**Edge Computing** 改變了這點。它讓你可以把**程式碼**（Function）部署到 CDN 的邊緣節點上執行。

### 應用場景

1. **A/B Testing**：在邊緣節點就決定要給使用者看 A 版還是 B 版頁面，不用回到源站。
2. **身分驗證**：在邊緣節點驗證 JWT Token，如果不合法直接擋掉，減輕源站負擔。
3. **個人化內容**：根據使用者的地理位置（GeoIP），在邊緣節點直接修改回應內容（例如顯示當地貨幣）。

支援邊緣部署的平台可以把這些程式放到靠近使用者的節點。Serverless 指的是不用自行管理伺服器，並不代表一定在邊緣執行；選平台時還要確認執行區域，以及資料庫是否仍在遠端。

## 為什麼你需要 CDN？

1. **速度**：就近存取，減少延遲（Latency）。
2. **可靠性**：如果有可用快取，且規則允許，源站故障時仍可能提供內容；備援導流則需要事先設定。
3. **安全性**：部分 CDN 方案提供 DDoS 防護和 WAF（Web Application Firewall），仍要依方案啟用、設定，也要確認源站的保護方式。
4. **成本**：快取可以減少回源流量，但是否省錢，要一起計算 CDN、源站流量與方案費用。

如果網站載入慢，可以先檢查圖片和靜態檔案能不能透過 CDN 提供。讓使用者少等一點，對閱讀體驗和 SEO 都有幫助，也值得花時間設定。
