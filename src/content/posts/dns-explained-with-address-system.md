在瀏覽器輸入 `www.google.com` 並按下 Enter 後，電腦需要先查出對應的 IP 位址，才知道去哪裡連線。這項查詢由 DNS 處理。

## 先來想像一個生活情境

假設朋友跟你說：「到美味咖啡找我。」

你打開 Google Maps 搜尋店名，查到它在快樂街 123 號，才知道要去哪裡。不過只有街名和門牌還不夠，不同城市可能有同名的街道，要把地區也寫清楚。網路位址也需要放在對應的網路範圍裡理解。

在網路的世界裡：

- **快樂街 123 號** = **IP 位址**（例如 `142.250.185.78`）
- **「美味咖啡」這個店名** = **域名（Domain Name）**（例如 `www.google.com`）
- **在 Google Maps 用店名查出地址** = **DNS**

拿到地址之後要走哪條路過去，則是路由器轉送封包的工作，不歸 DNS 管。

## 什麼是 IP 位址？

電腦透過網路介面使用 IP 位址收送資料。你可以先把它當成網路上的地址，它長這樣：

```
142.250.185.78
```

不過，IP 不一定和電腦一對一：一台電腦可以有多個位址，家裡多台裝置也可能透過路由器共用一個對外 IP。不同家庭還能使用相同的私有 IP，因為它們分屬不同的內部網路。

但 `142.250.185.78` 這種地址很難記。

就像約朋友時，你會說「到美味咖啡找我」，因為店名比門牌號碼好記。

## DNS — 網路世界的電話簿

DNS 的全名是 **Domain Name System**（域名系統）。它做的事情很簡單：

> **把你記得住的名字（域名），翻譯成電腦看得懂的地址（IP）。**

就像一本超級電話簿：

<div class="table-wrapper" tabindex="0" role="group" aria-label="表格（可水平捲動）">

| 你輸入的（域名）   | DNS 翻譯出的（IP 位址） |
| ------------------ | ----------------------- |
| `www.google.com`   | `142.250.185.78`        |
| `www.facebook.com` | `157.240.214.35`        |
| `www.youtube.com`  | `142.250.190.46`        |

</div>

表中的 IP 是說明用的例子，不是這些網站永遠固定的地址。輸入網址後，DNS 會查出當下的結果，電腦再用這個地址連線。

## DNS 查詢是怎麼進行的？

假設你要去一家叫「美味咖啡」的店，可以用找地址的過程來理解 DNS 查詢：

### 第一步：先問自己（瀏覽器快取）

「我之前去過嗎？記得地址嗎？」

如果你最近才去過，你的大腦（瀏覽器）還記得地址，就不用再查了。這就是**快取（Cache）**。

### 第二步：問家人（作業系統快取）

「媽，你知道美味咖啡在哪嗎？」

你的電腦作業系統也會記住最近查過的 DNS 結果。

### 第三步：打電話問 104（遞迴 DNS 伺服器）

如果家裡沒人知道，你就打電話問 104 查號台。遞迴 DNS 伺服器就像這個查號台，可能由 ISP（網路服務提供商）提供，也可能是你或瀏覽器設定的公共 DNS。

### 第四步：查號台從最上層開始往下問（根域名伺服器 → 頂級域名伺服器 → 權威域名伺服器）

查號台如果也不知道，就會從最上層的根域名伺服器問起，依照對方的指示一層層往下找，直到問到負責這個域名的權威域名伺服器：

1. **根域名伺服器**：「`.com` 的資料要去哪裡查？」
2. **頂級域名伺服器**：「`google.com` 的資料要去哪裡查？」
3. **權威域名伺服器**：「`www.google.com` 的 IP 是 `142.250.185.78`！」

最後，答案傳回電腦。有快取時不必完整跑一遍；實際耗時則會受網路延遲和 DNS 伺服器狀況影響。

用圖來看整個流程：

```mermaid
sequenceDiagram
    participant Browser as 你的瀏覽器
    participant Resolver as 遞迴 DNS 伺服器
    participant Root as 根域名伺服器
    participant TLD as 頂級域名伺服器
    participant Auth as 權威域名伺服器

    Browser->>Resolver: www.google.com 的 IP 是什麼？
    Resolver->>Root: .com 要去哪查？
    Root-->>Resolver: 去問 .com 頂級域名伺服器
    Resolver->>TLD: google.com 要去哪查？
    TLD-->>Resolver: 去問 google.com 的權威伺服器
    Resolver->>Auth: www.google.com 的 IP？
    Auth-->>Resolver: 142.250.185.78
    Resolver-->>Browser: 142.250.185.78
```

## 常見的 DNS 記錄類型

DNS 不只能翻譯 IP 位址，它其實像一本功能很多的通訊錄：

<div class="table-wrapper" tabindex="0" role="group" aria-label="表格（可水平捲動）">

| 記錄類型  | 功能                                      | 生活化比喻                           |
| --------- | ----------------------------------------- | ------------------------------------ |
| **A**     | 域名 → IPv4 位址                          | 門牌號碼（最常用）                   |
| **AAAA**  | 域名 → IPv6 位址                          | 新式門牌號碼（地址不夠用了，升級版） |
| **CNAME** | 域名 → 另一個域名                         | 「這家搬到對面去了，去那邊找」       |
| **MX**    | 域名 → 收信伺服器的主機名稱（含優先順序） | 信箱地址（專門收信的）               |
| **TXT**   | 文字資訊                                  | 門口的公告欄                         |

</div>

MX 記錄存的是主機名稱，寄件端還要再查它的 A／AAAA 記錄，才拿得到 IP。

舉個例子：當你設定自訂域名給你的部落格時（像是我把自己的網站指向 Cloudflare），可以用 **A／AAAA 記錄** 把名稱直接指向 IP，或用 **CNAME 記錄** 把子網域（例如 `blog.worksbyaaron.com`）指向平台提供的主機名稱（例如 `xxx.pages.dev`），DNS 會再沿著那個名稱查出 IP。

`worksbyaaron.com` 本身是這個 DNS 區域的最上層（zone apex），依規範不能設 CNAME：CNAME 不能和其他記錄並存，而這一層一定有 SOA 和 NS 記錄。Cloudflare 能讓你在這裡填 CNAME，是靠 CNAME flattening 在回應查詢時直接回傳最終的 IP。

CNAME 的「搬到對面」只是在查詢時沿著另一個名稱找位址，不會自行改掉瀏覽器網址。要讓網址列跳到新網址，還需要網站伺服器回傳 HTTP 重新導向。

## 為什麼有時候網站打不開？

### 「DNS 解析失敗」

這就像你查電話簿找不到這個人的號碼。可能的原因：

- 域名打錯了（地址寫錯）
- DNS 伺服器暫時故障（查號台下班了）
- 域名過期沒續約（這家店已經關了）

### 「剛換完域名指向，但還是連到舊的」

DNS 有快取機制，你的電腦會記住之前查到的結果。通常需要等幾分鐘到幾小時，快取才會更新。這就像店家搬了家，但 Google Maps 上的地址可能還是舊的，需要等它更新。

TTL（Time To Live）是 DNS 記錄允許被快取的時間，可以想成資訊的保質期。它不是「修改後固定要等多久」；已經存下的舊結果，通常要等原本的 TTL 到期才會重新查詢。

### 「公司的內部網站在外面連不上」

有些域名只在公司內部的 DNS 有設定。就像公司內部的分機號碼，外面的人打不進來。

## 你可以自己試試看

### 查詢域名的 IP 位址

在你的電腦打開終端機（Terminal），輸入：

```bash
nslookup google.com
```

結果會列出 `google.com` 目前解析到的 IP 位址。

### 換一個 DNS 伺服器

電腦可能透過路由器使用 ISP（像是中華電信）提供的 DNS，也可能有另外設定。常見的公共 DNS 有：

<div class="table-wrapper" tabindex="0" role="group" aria-label="表格（可水平捲動）">

| DNS 服務       | 位址      | 特色         |
| -------------- | --------- | ------------ |
| Google DNS     | `8.8.8.8` | 速度快、穩定 |
| Cloudflare DNS | `1.1.1.1` | 主打隱私保護 |

</div>

換 DNS 就像換一本電話簿，查詢速度和安全性也可能跟著改變。

## 結語

下次遇到網址打不開，可以先查 DNS 是否有回傳 IP，再確認快取和所使用的 DNS 伺服器。
